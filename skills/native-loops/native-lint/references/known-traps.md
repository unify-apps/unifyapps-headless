# Known traps

Tool and platform behaviours that look like success and are not, or that refuse a write the brief did not expect. `task-lint` of this block ([task lint](task-lint.md)) rewrites or refuses a brief that walks into one. Each row names the version or PR that retires it; the lint applies a row only while the installed versions are older. T01, T03, T04, T09, T10, T17, T19, T22 and T23 hold on MOBILE only; the rest hold on WEB too, and `task-lint --platform WEB` runs only those. Evidence: the feedback records and builder reports of the first native app builds, and the [device traps](../../loop-orchestrator/references/device-traps.md) a UI rebuild met on the simulator.

| id | Trap | Detect in a brief or task body | Rewrite or rule | Retired by |
| --- | --- | --- | --- | --- |
| T01 | A Module block takes only its own events (`onOutputChange`, …); `onNavigate`, `onClick` on a Module are refused | `update_event_actions` or an event name on a Module block that is not in the Module sheet | Put the event on the block inside the module, or on the page | — |
| T02 | `apply_page_edits` ops are `set` and `unset` only; `update_blocks` takes `edits`, not `updates` | ops other than set/unset; the key `updates` | Use `set`/`unset`; `edits` | — |
| T03 | `appearance.interactions` on a Pressable is refused by `update_blocks` ("how the inspector shows event bindings") | a brief that updates `appearance.interactions` | Set it at `create_block` time, or recreate the block | platform PR #31453 (`update_blocks` accepts it on Pressable) |
| T04 | TextInput label add-on accepts `color`, `variant`, `weight` only; `lineHeight`/`letterSpacing` are refused | `addOns.label.appearance.lineHeight` or `.letterSpacing` | Drop them, or wait for the platform deploy | platform PR #31453 |
| T05 | `removeActionIds` wants `act_` ids; plans and caches show `evt_` ids | `evt_` inside `removeActionIds` | Read the block's events live and map each `evt_` to its `act_` | — |
| T06 | `create_block` camelCases a snake_case `displayName` with a misleading warning | a snake_case name in a create | Name blocks in camelCase up front; read the name back | — |
| T07 | Folder and data-source names are unique app-wide, not per page (`constants` became `constants1`) | a folder or data-source name that exists elsewhere in the app | Check `cache keys`/`cache ds` across the app first; qualify the name | — |
| T08 | A boolean `initialValue` on a page variable returns an opaque HTTP 500 | `initialValue: true|false` as JSON booleans | Write the string `"true"`/`"false"` or the value the sheet names | — |
| T09 | A MOBILE page reads `native/blocks/<x>` sheets; the write gate may still demand the web `blocks/<x>` sheet | a mobile brief naming only one family | Read both sheets in the first knowledge read | — |

| T11 | `runBehaviour` and `isPublic` have no read-back on any tool | a proof line that promises to read them back | Mark them `unverified` up front with the raw entity read as the only check | — |
| T12 | Standard objects (`e_interface`, `e_component`) refuse `apply_record_edits` | a record edit on a standard object | Use the surface tool (`update_app_settings`, page settings) | — |

| T14 | A knowledge sheet id the tenant does not serve answers `notFound` | a brief naming a sheet | Check the sheet list first; name only served sheets | — |
| T15 | A changed asset keeps its old picture when the URL is reused (no cache TTL on the phone or CDN) | an upload that reuses a file name | Every changed asset gets a new file name (content hash) | — |
| T16 | A page's cache entry can be a stale hit after edits outside UnifyApps Headless; child order in `cache outline` was alphabetical in one version | a write built on a cache read that sends no `expectedVersions` | Pass the cached page's version in `expectedVersions`; on "Version changed", read it live and redo the edit | UnifyApps Headless ≥ 3.50.0 (order) |
| T17 | Builders have no argent MCP tools; `ToolSearch argent` finds nothing | a builder brief that names `mcp__argent__*` | Brief `argent run <tool> --args '{json}'` from Bash with the reserved device id | — |
| T18 | Claude Code auto mode refuses `deploy_workflow` from a builder as a production deploy on UAT | a deploy task sent to a builder under auto mode | Run the deploy from the main session, or ask the person for the permission rule once | — |
| T19 | The loops never publish the app: the Preview app runs drafts. A new or changed source that still answers `forbidden datasource` on the device is reported, not published | a brief that publishes the app to check a data source | Check the source on the Preview app, on its draft; if it answers `forbidden datasource`, record the check as not proven with that reason and leave the publish to the person | — |
| T20 | `describe_callable_workflow` returns inputs only; the STOP output is readable only through `inspect_workflow_run` with node ids | an automation proof that reads the callable description | Read the run's STOP node | — |
| T21 | PinInput code length (5 vs 6) and other spec facts were guessed | a code length not stated by the spec | Ask once; never pick a length | — |
| T22 | `update_page_settings` cannot write page transitions or navigator type | a brief that writes `pageTransitionBehavior` or `navigatorType` | Route to the main session or the builder UI as a manual step | platform PR #31453 (transitions) |
| T23 | A `{{ … }}` expression inside native custom style JSON (`customStyles`, `customCSS`) is not evaluated on the phone; it raises a parse toast over the tab bar ([device trap D01](../../loop-orchestrator/references/device-traps.md)) | `{{` on a line that names `customStyles`, `customCSS` or a custom style (a line that warns against it is skipped) | Literal values per state (one block per state, shown by condition), or an appearance property the block sheet says takes a binding | — |
| T24 | A page built with a data source and no task for its loading states shows blank regions and jumps when the data lands: the design rarely has a loading frame, so no builder adds a skeleton | a tasks file that lays out a page and binds it to a data source, with no task on that page naming its loading states or a skeleton (checked across the whole file, reported once, on the first `page-bind` that reads the source) | The page's loading-states `page-bind` after its bind task ([native-loading-states plan](../../native-loading-states/references/plan.md) § 5), or the loading states in the `page-bind` that adds the source | — |
