# Control flow — `if` / `while` / `for_each` / `break` / `continue`

Loaded the moment a scenario demands branching, iteration, or per-item repetition (an intermittent surface, "for each …", "until …"). One rung above JS on the escape ladder; below everything typed.

A conditional means green no longer tells you which branch ran. Most impulses are something else: intermittent cookie/consent banner → the one honest `if` (condition `visible`, a click in `then`); "retry / wait for it" → `navigatesTo`/`revealsElement` or a retrying assertion; "log in if needed" → setup, not a step; "same for each input" → `for_each` over inline `over.rows` **only** for a fixed set carried in the step — a stored dataset is driven by the binding on `Deliver Steps`, never `for_each`. Justify any control flow in `observations`.

**"Last resort" is relative — control flow sits one rung ABOVE `execute_js`.** The strict order: linear typed steps → `if`/`while`/`for_each` → JS, each rung reached only when the one above can't express the scenario. When the scenario genuinely demands iteration or branching, the construct IS the sanctioned tool — "scan pages until the next-page button is disabled" is a `while` exiting on that button's `disabled` condition; a fixed input set is a `for_each` — and reaching past a construct that can carry the logic to a JS blob is a defect: constructs stay in the grammar (compiled, editable, readable, each iteration guarded and retried); JS forfeits all of it.

**A condition is a check, not an expression**: `{ type, selector?, expected? }`, `type` ∈ `visible|text|empty|value_not_empty|attribute|url_is|title|page_loaded|element_state|clickable|text_on_page|text_not_on_page`. This is the WHOLE condition vocabulary — it is NOT the assertion vocabulary. `present`/`absent` and the bare states (`hidden`/`enabled`/`disabled`/`checked`/`unchecked`) are assertion-only; as a condition they don't compile (the compiler rejects the type outright). Map them instead: **"element absent / not present" → `element_state` with `expected: "hidden"`** (compiles to `toBeHidden()`, which also passes for a zero-count/detached locator — the correct probe for a `while … reload` waiting on a row to appear or vanish); **"element present / shown" → `visible`**; any other state → `element_state` with the state in `expected`. `text`/`url_is`/`title`/`text_on_page`/`text_not_on_page` take string `expected`; `element_state` takes `expected` ∈ `visible|hidden|enabled|disabled|checked|unchecked`; `attribute` takes `{name,value}`; the rest take none. `text_on_page`/`text_not_on_page` are page-level (no `selector`). Conditions never resolve dataset tokens — literals only. **For element state, always use `element_state` with the state in `expected`** — only `element_state` (and `visible`) map to their own editor variants and to a compilable condition.

`if` has `then` (+ optional `else`; else-if = an `if` nested in `else`). `while` has `children` + a `maxIterations` cap. `for_each` has `over.rows` (inline row objects) + `children`; a child references the current row's column with `<<Column>>`. `break`/`continue` only inside a loop. **Child step indices restart at 1 inside every block** (`then`, `else`, `children`) — never continue the outer numbering.
